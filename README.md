# AI Council 3.14.0

The council no longer treats a bad argument as proof of the opposite, and no longer treats a pile of claims as a stronger proof. `FallacyFallacyPolicy` flags a verdict that a thesis is false merely because a supporting argument was flawed. `GishGallopPolicy` flags a verdict that rests on a flood of unrelated points, or on a bare list of six or more claims with no warrant that is then declared true. Naming either error is not itself an error. The coordinator cannot close on a fallacy in the other side's wording, or on the number of points, and experts on a structured task are told that an error is not a verdict. The screen version matches Gradle again: `3.14.0` / versionCode `181` (the previous screen still showed `3.12.0`).

# AI Council 3.13.0

A local relative-privation / «not as bad as» check now flags conclusions that a problem is acceptable or minor merely because a worse problem exists. Naming that error is not itself an error. The coordinator cannot close a verdict on «there are worse problems» alone, and experts on a structured task are reminded that a worse problem does not cancel the current cost and risk. Version on screen matches Gradle: `3.13.0` / versionCode `180`.

# AI Council 3.5.0

The council now keeps the unseen cost on the ledger and refuses to treat an easy metric as the whole decision. `SeenAndUnseenPolicy` flags a verdict that counts only the visible effect (Bastiat: the broken window is not a gain). `StreetlightPolicy` flags a verdict that keeps only what is easy to measure (McNamara / streetlight). Naming either error is not itself an error. When such a signal is on the local map, `CoordinatorCue` tells the coordinator the exact way not to close — novelty, pity, a red herring, tu quoque and the other unwired hypotheses now get a specific instruction too, capped at four notes so the task is not drowned. Experts are told the same rule in the shared baseline. Version on screen matches Gradle: `3.5.0` / versionCode `172`.
