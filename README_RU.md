# AI Council 2.1.0

Современная оболочка 2.1.0: чернильные поверхности, мятный акцент, плавающая навигация и контент от края до края на Android 11+. Debug APK собирается в GitHub Actions и публикуется в Releases.

> English overview: [README.md](README.md)

AI Council — Android-приложение для работы с несколькими ИИ-провайдерами: независимые ответы, аудит, глубокий анализ, локальные серверы, поиск источников, импорт документов и экспорт отчётов.

## 2.0.0 — основа миграции Android 16

- `versionName` — `2.0.0`, `versionCode` — `47`.
- Android Gradle Plugin 9.4.0, Gradle 9.6.0, `compileSdk 36`, `targetSdk 36`.
- Добавлен потоковый клиент OkHttp для OpenAI-совместимого `POST /v1/chat/completions`: отдельные колонки обновляются по мере поступления фрагментов; отмена закрывает активные вызовы. Повторы ограничены ответами 429 и 5xx, а диагностика проходит через существующие `ProviderErrorFormatter` и `SecretRedactor`.
- История, проекты и черновик сохраняются в локальной SQLite-базе через `LocalDataStore`; при первом запуске переносится allow-list старых ключей `history`, `projects`, `draftPrompt`, `draftFollowUp`, `draftMode`. Ключи API и роли экспертов в базу миграции не входят.
- Добавлена структурированная модель результата `CouncilResultModel`, обработка сохранённых частичных ответов после прерывания процесса и throttling отрисовки потоковых токенов.
- Стратегии выполнения вынесены в Android-независимый `CouncilExecutionEngine`: быстрый ответ, аудит, совет и глубокий анализ с взаимной критикой; сценарии покрыты 30 автономными проверками. UI и часть интеграционной логики всё ещё находятся в `MainActivity`.
- В CI предусмотрены статическая проверка, автономные Java smoke tests и сборка debug APK с загрузкой артефакта; фактический удалённый запуск должен быть подтверждён в самом репозитории GitHub.
- Поисковые API Brave Search, Tavily (оба — при наличии пользовательских ключей), Wikipedia Search и DuckDuckGo Instant Answer используют отдельный OkHttp-клиент с fixed HTTPS allowlist; загрузка исходных HTML-страниц остаётся отдельным проверяемым путём.
- Оркестрация поиска и HTML-извлечения вынесена из `MainActivity` в Android-независимый `WebSearchService`: источники запускаются параллельно, результаты ранжируются общей `WebSearchPolicy`, URL канонизируются и дедуплицируются, а детальный режим загружает не более двух публичных HTTPS-страниц с разных доменов.
- Обработка локального OCR вынесена из Activity в `ocr/OcrDocumentProcessor`: фото учитывают EXIF-поворот и декодируются с уменьшением разрешения; PDF обрабатывается постранично — сначала извлекается текстовый слой PDFBox, а системный `PdfRenderer` и OCR используются только на страницах без извлекаемого текста. Предпросмотр отмечает источник текста и непрочитанные страницы. `OcrInputPolicy` покрыт 18 автономными policy-тестами, гибридный путь проверяется отдельными 5 интеграционными smoke-проверками на API-shape stubs.
- Глобальный `usesCleartextTraffic=true` удалён. Network Security Config блокирует cleartext по умолчанию и разрешает loopback/локальные имена. **Ограничение:** произвольный HTTP по private IPv4 LAN-адресу (например, `192.168.1.x`) всё ещё может блокироваться конфигурацией Android; совместимость нужно подтвердить на устройстве.

## Текущий этап OCR — гибридный PDF-процессинг

Обычный PDF-импорт и отдельный OCR-импорт используют единый локальный процессор. Для каждой страницы сначала запрашивается текстовый слой PDFBox; отрисовка страницы через `PdfRenderer` и OCR запускаются лишь при пустом текстовом слое. Для OCR кириллицы можно выбрать русский или украинский язык, а текстовый слой не требует скачивания OCR-модели. **Лимит PDF настраивается в UI** (кнопка «Лимит страниц PDF»): 5 страниц по умолчанию или до 20 страниц по выбору пользователя. Настройка сохраняется на устройстве (`ocr_pdf_max_pages`) и применяется к обычному PDF-импорту и OCR сканированных PDF. Состояние проверок и ограничения тестов указаны в `TEST_RESULTS_RU.md`.

## Важно о полноте миграции

Это частичная реализация задания, а не заявление о полном завершении. Все сетевые пути исходников приложения используют отдельные OkHttp-клиенты: чатовый SSE-поток, поисковые API, HTML-загрузка, OCR-модели и каталог `/models`. Для поиска/HTML используются фиксированный allowlist API, DNS pinning, повторная проверка редиректов и ограничения тела ответа; каталог моделей ограничен 250 КБ и не следует редиректам автоматически. Для моделей OCR `rus` и `ukr` добавлены закреплённые размеры и SHA-512 контрольные суммы: и существующая модель, и новый файл проверяются до использования/установки. Загрузка моделей OCR переведена на отдельный клиент OkHttp с DNS-проверкой и закреплением проверенных адресов, отключёнными редиректами, ограничением размера и отменой из диалога; `OcrModelIntegrityPolicy` проверяет точный размер и SHA-512 перед установкой. Расширяемый каталог дополнительных языков и runtime-проверка на устройстве пока не реализованы. `MainActivity` всё ещё остаётся крупным классом (после выделения OCR — около 2900 строк); llama.cpp/JNI, каталог GGUF и автономная генерация на устройстве не реализованы. В этой рабочей среде нет Android SDK и Gradle, поэтому APK не собран. Проверка на физическом телефоне с 6 ГБ RAM и планшете не выполнялась, раздел 10 приёмки не пройден. Подробности — `TEST_RESULTS_RU.md` и `ROADMAP_RU.md`.

## Продолжение 2.0.0 — каталог моделей на OkHttp

- Запросы `/models` для OpenAI-совместимых API, Ollama и LM Studio вынесены из `MainActivity` в `ProviderModelsClient`; в Activity остаются выбор модели, разбор списка и обновление интерфейса.
- Клиент отключает автоматические редиректы, ограничивает тело ответа 250 КБ, использует тайм-ауты, регистрирует активные вызовы для отмены, а детали ошибок пропускает через форматтер и очистку секретов.
- Перед вызовом применяется `EndpointPolicy`/`LocalAiPolicy`. Сохранённый облачный ключ не передаётся на loopback, private LAN, `.local` и другие endpoint-ы, определённые как локальные. «Только локальные ИИ» блокирует облачный каталог до сетевого запроса.
- `ProviderModelsClientSmokeTest`: 9/9 проверок на API-штумах OkHttp. Они проверяют границы безопасности и отмену, но не выполняют реальный сетевой запрос.

## Продолжение 2.0.0 — безопасная загрузка OCR-моделей

- Загрузчик `OcrModelManager` переведён на OkHttp 4.12.0. Автоматические HTTP/HTTPS redirect-ы отключены, DNS-адреса перед соединением проверяются как публичные unicast и закрепляются для самого запроса.
- Скачивание `rus`/`ukr` идёт только с закреплённого HTTPS-адреса версии `tessdata_fast` 4.1.0; заявленный и фактический размер ограничиваются, SHA-512 проверяется до установки, существующая модель сохраняется как резерв на время замены.
- Для OCR изображений и сканированных PDF показан отдельный диалог загрузки с кнопкой отмены; отмена закрывает активный OkHttp-вызов и не устанавливает частично скачанный файл.
- `tools/verify_project.py` и `tools/desktop_smoke/run.sh` следует запускать после каждой правки; актуальные числа зафиксированы в `TEST_RESULTS_RU.md`. Smoke runner использует API-shape stubs для OkHttp, поэтому результаты не заменяют настоящую сборку Gradle, проверку загрузки или запуск на Android.

## История изменений: 1.37.0 — предупреждение о секрете перед отправкой

- Перед передачей задачи или уточняющего вопроса провайдерам приложение локально проверяет текст на распространённые API-ключи, Bearer-токены, credential-поля, секреты в URL-параметрах и блоки закрытых ключей.
- При обнаружении вероятных секретов пользователь может отправить замаскированную копию, отправить исходный текст осознанно или отменить отправку.
- Маскирование переиспользует `SecretRedactor`; внешние сервисы не вызываются для самой проверки.
- Ограничение: это best-effort проверка, она не гарантирует обнаружение неизвестных форматов секретов и не заменяет ручную проверку файлов перед отправкой.

## Новое в 1.36.0 — умнее, удобнее и доступнее

- **Приблизительная оценка токенов** для черновика выполняется локально и помогает понимать относительный размер задачи до отправки. Это эвристика, а не фактический счётчик токенов провайдера.
- **Автовыбор стратегии** вынесен в отдельную тестируемую политику и распознаёт распространённые запросы на русском, украинском и английском языках. Он учитывает, какие эксперты настроены и какие отмечены бесплатными; всегда остаётся возможность вручную выбрать стратегию.
- **Голосовой ввод** показывает альтернативы распознавания, если система вернула несколько вариантов. Пользователь выбирает вариант сам; задача не отправляется автоматически.
- **Очистка черновика** доступна в один шаг с подтверждением, не затрагивая историю и проекты.
- В настройках каждого подключения есть кнопка **«Показать / Скрыть» API-ключ**; видимость меняется только в поле ввода и не отключает шифрование сохранённого ключа.
- Обновления статуса помечены для accessibility live region, чтобы экранные дикторы могли сообщать о состоянии операций.
- Оценка токенов обновляется с задержкой после остановки ввода, чтобы длинные вставки и документы не заставляли пересчитывать весь текст при каждом нажатии клавиши.
- Новых Android-разрешений и сторонних библиотек не добавлено.

## Новое в 1.35.0 — современный интерфейс и голосовой черновик

- Обновлена визуальная иерархия главного экрана: новый заголовок «Ваш ИИ-штаб», спокойные поверхности, акцентная карточка задачи и более явная основная кнопка.
- Добавлена диктовка задачи через системный speech recognizer Android. Распознанный текст только вставляется в черновик; до отправки его можно исправить.
- Добавлен счётчик символов задачи до лимита в 100 000 символов, предупреждение появляется с 90%.
- Голосовой ввод не добавляет новое Android-разрешение и не требует отдельной библиотеки.

## Новое в 1.34.0 — дополнительная очистка секретов в API-ошибках

- Перед показом диагностического ответа провайдера приложение теперь очищает не только ключ, настроенный в этом профиле, но и распространённые форматы секретов: OpenAI-style `sk-…`, Google `AIza…`, Groq `gsk_…`, xAI `xai-…`, Hugging Face `hf_…`, GitHub tokens и AWS access key IDs.
- Маскируются значения в полях `api_key`, `access_token`, `client_secret`, `password`, `token`, заголовках `Authorization: Bearer …`, URL-параметрах ключей и блоках закрытых ключей.
- Очистка реализована отдельным `SecretRedactor`, используется форматтером HTTP-ошибок и покрыта автономными Java-тестами. Новых сторонних зависимостей и Android-разрешений не добавлено.
- Это best-effort фильтр текста ошибок, а не гарантия обнаружения любого неизвестного формата секрета; перед публикацией отчёта всё равно проверяйте текст.



## Новое в 1.33.0 — понятная диагностика API и отмена запросов

- При HTTP-ошибке AI Council показывает вероятную причину и следующее действие: проверьте ключ для 401, права доступа для 403, модель/URL для 404, квоту для 429 и размер задачи для 413.
- Ответ провайдера сохраняется как дополнительная подсказка, ограничивается 1200 символами и очищается от точно совпадающего API-ключа и распространённого Bearer-токена.
- Если пользователь останавливает запрос во время чтения ответа, приложение показывает отмену, а не путает её с неисправностью интернета.
- Тайм-аут, отмена и прерывание параллельного этапа получают отдельные сообщения.
- В проект добавлены 11 автономных проверок форматирования HTTP-ошибок.
