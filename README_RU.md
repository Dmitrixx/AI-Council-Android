# AI Council 2.1.0

Современная оболочка 2.1.0: чернильные поверхности, мятный акцент, плавающая навигация и контент от края до края на Android 11+. Debug APK собирается в GitHub Actions и публикуется в Releases.


AI Council — Android-приложение для работы с несколькими ИИ-провайдерами: независимые ответы, аудит, глубокий анализ, локальные серверы, поиск источников, импорт документов и экспорт отчётов.

## 2.0.0 — основа миграции Android 16

- `versionName` — `2.0.0`, `versionCode` — `47`.
- Android Gradle Plugin 9.4.0, Gradle 9.6.0, `compileSdk 36`, `targetSdk 36`.
- Добавлен потоковый клиент OkHttp для OpenAI-совместимого `POST /v1/chat/completions`: отдельные колонки обновляются по мере поступления фрагментов; отмена закрывает активные вызовы. Повторы ограничены ответами 429 и 5xx, а диагностика проходит через существующие `ProviderErrorFormatter` и `SecretRedactor`.
- История, проекты и черновик сохраняются в локальной SQLite-базе через `LocalDataStore`; при первом запуске переносится allow-list старых ключей `history`, `projects`, `draftPrompt`, `draftFollowUp`, `draftMode`. Ключи API и роли экспертов в базу миграции не входят.
- Добавлена структурированная модель результата `CouncilResultModel`, обработка сохранённых частичных ответов после прерывания процесса и throttling отрисовки потоковых токенов.
- Стратегии выполнения вынесены в Android-независимый `CouncilExecutionEngine`: быстрый ответ, аудит, совет и глубокий анализ с взаимной критикой; сценарии покрыты 30 автономными проверками. UI и часть интеграционной логики всё ещё находятся в `MainActivity`.
- В CI предусмотрены статическая проверка, автономные Java smoke tests и сборка debug APK с загрузкой артефакта; фактический удалённый запуск должен быть подтверждён в самом репозитории GitHub.
- Поисковые API Brave Search, Tavily (оба — при наличии пользовательских ключей), Wikipedia Search и DuckDuckGo Instant Answer используют отдельный OkHttp-клиент с fixed HTTPS allowlist; загрузка исходных HTML-страниц остаётся отдельным проверяемым путём.
- Оркестрация поиска и HTML-извлечения вынесена из `MainActivity` в Android-независимый `WebSearchService`: источники запускаются параллельно, результаты ранжируются общей `WebSearchPolicy`, URL канонизируются и дедуплицируются, а детальный режим загружает не более двух публичных HTTPS-страниц с разных доменов.
- Обработка локального OCR вынесена из Activity в `ocr/OcrDocumentProcessor`: фото учитывают EXIF-поворот и декодируются с уменьшением разрешения; PDF обрабатывается постранично — сначала извлекается текстовый слой PDFBox, а системный `PdfRenderer` и OCR используются только на страницах без извлекаемого текста. Предпросмотр отмечает источник текста и непрочитанные страницы. `OcrInputPolicy` покрыт 18 автономными policy-тестами, гибридный путь проверяется отдельными 5 интеграционными smoke-проверками на API-shape stubs.
- Глобальный `usesCleartextTraffic=true` удалён. Network Security Config блокирует cleartext по умолчанию и разрешает loopback/локальные имена. **Ограничение:** произвольный HTTP по private IPv4 LAN-адресу (например, `192.168.1.x`) всё ещё может блокироваться конфигурацией Android; совместимость нужно подтвердить на устройстве.

## Текущий этап OCR — гибридный PDF-процессинг

Обычный PDF-импорт и отдельный OCR-импорт используют единый локальный процессор. Для каждой из первых пяти страниц сначала запрашивается текстовый слой PDFBox; отрисовка страницы через `PdfRenderer` и OCR запускаются лишь при пустом текстовом слое. Для OCR кириллицы можно выбрать русский или украинский язык, а текстовый слой не требует скачивания OCR-модели. Лимит PDF настраивается в раскрываемой группе импорта: 5 страниц по умолчанию или до 20 страниц по выбору пользователя. Настройка сохраняется на устройстве и применяется к обычному PDF-импорту и OCR сканированных PDF. Состояние проверок и ограничения тестов указаны в `TEST_RESULTS_RU.md`.

## Важно о полноте миграции

Это частичная реализация задания, а не заявление о полном завершении. Все сетевые пути исходников приложения используют отдельные OkHttp-клиенты: чатовый SSE-поток, поисковые API, HTML-загрузка, OCR-модели и каталог `/models`. Для поиска/HTML используются фиксированный allowlist API, DNS pinning, повторная проверка редиректов и ограничения тела ответа; каталог моделей ограничен 250 КБ и не следует редиректам автоматически. Для моделей OCR `rus` и `ukr` добавлены закреплённые размеры и SHA-512 контрольные суммы: и существующая модель, и новый файл проверяются до использования/установки. Загрузка моделей OCR переведена на отдельный клиент OkHttp с DNS-проверкой и закреплением проверенных адресов, отключёнными редиректами, ограничением размера и отменой из диалога; `OcrModelIntegrityPolicy` проверяет точный размер и SHA-512 перед установкой. Расширяемый каталог дополнительных языков и runtime-проверка на устройстве пока не реализованы. `MainActivity` всё ещё остаётся крупным классом (после выделения OCR — около 2900 строк); llama.cpp/JNI, каталог GGUF и автономная генерация на устройстве не реализованы. В этой рабочей среде нет Android SDK и Gradle, поэтому APK не собран. Проверка на физическом телефоне с 6 ГБ RAM и планшете не выполнялась, раздел 10 приёмки не пройден. Подробности — `TEST_RESULTS_RU.md` и `ROADMAP_RU.md`.

## Продолжение 2.0.0 — каталог моделей на OkHttp

- Запросы `/models` для OpenAI-совместимых API, Ollama и LM Studio вынесены из `MainActivity` в `ProviderModelsClient`; в Activity остаются выбор модели, разбор списка и обновление интерфейса.
- Клиент отключает автоматические редиректы, ограничивает тело ответа 250 КБ, использует тайм-ауты, регистрирует активные вызовы для отмены, а детали ошибок пропускает через форматтер и очистку секретов.
- Перед вызовом применяется `EndpointPolicy`/`LocalAiPolicy`. Сохранённый облачный ключ не передаётся на loopback, private LAN, `.local` и другие endpoint-ы, определённые как локальные. «Только локальные ИИ» блокирует облачный каталог до сетевого запроса.
- `ProviderModelsClientSmokeTest`: 9/9 проверок на API-штумах OkHttp. Они проверяют границы безопасности и отмену, но не выполняют реальный сетевой запрос.

## Продолжение 2.0.0 — безопасная загрузка OCR-моделей

- Загрузчик `OcrModelManager` переведён на OkHttp 4.12.0. Автоматические HTTP/HTTPS redirect-ы отключены, DNS-адреса перед соединением проверяются как публичные unicast и закрепляются для самого запроса.
- Скачивание `rus`/`ukr` идёт только с закреплённого HTTPS-адреса версии `tessdata_fast` 4.1.0; заявленный и фактический размер ограничиваются, SHA-512 проверяется до установки, существующая модель сохраняется как резерв на время замены.
- Для OCR изображений и сканированных PDF показан отдельный диалог загрузки с кнопкой отмены; отмена закрывает активный OkHttp-вызов и не устанавливает частично скачанный файл.
- `tools/verify_project.py` и `tools/desktop_smoke/run.sh` следует запускать после каждой правки; актуальные числа зафиксированы в `TEST_RESULTS_RU.md`. Smoke runner использует API-shape stubs для OkHttp, поэтому результаты не заменяют настоящую сборку Gradle, проверку загрузки или запуск на Android.

## История изменений: 1.37.0 — предупреждение о секрете перед отправкой

- Перед передачей задачи или уточняющего вопроса провайдерам приложение локально проверяет текст на распространённые API-ключи, Bearer-токены, credential-поля, секреты в URL-параметрах и блоки закрытых ключей.
- При обнаружении вероятных секретов пользователь может отправить замаскированную копию, отправить исходный текст осознанно или отменить отправку.
- Маскирование переиспользует `SecretRedactor`; внешние сервисы не вызываются для самой проверки.
- Ограничение: это best-effort проверка, она не гарантирует обнаружение неизвестных форматов секретов и не заменяет ручную проверку файлов перед отправкой.

## Новое в 1.36.0 — умнее, удобнее и доступнее

- **Приблизительная оценка токенов** для черновика выполняется локально и помогает понимать относительный размер задачи до отправки. Это эвристика, а не фактический счётчик токенов провайдера.
- **Автовыбор стратегии** вынесен в отдельную тестируемую политику и распознаёт распространённые запросы на русском, украинском и английском языках. Он учитывает, какие эксперты настроены и какие отмечены бесплатными; всегда остаётся возможность вручную выбрать стратегию.
- **Голосовой ввод** показывает альтернативы распознавания, если система вернула несколько вариантов. Пользователь выбирает вариант сам; задача не отправляется автоматически.
- **Очистка черновика** доступна в один шаг с подтверждением, не затрагивая историю и проекты.
- В настройках каждого подключения есть кнопка **«Показать / Скрыть» API-ключ**; видимость меняется только в поле ввода и не отключает шифрование сохранённого ключа.
- Обновления статуса помечены для accessibility live region, чтобы экранные дикторы могли сообщать о состоянии операций.
- Оценка токенов обновляется с задержкой после остановки ввода, чтобы длинные вставки и документы не заставляли пересчитывать весь текст при каждом нажатии клавиши.
- Новых Android-разрешений и сторонних библиотек не добавлено.

## Новое в 1.34.0 — дополнительная очистка секретов в API-ошибках

- Перед показом диагностического ответа провайдера приложение теперь очищает не только ключ, настроенный в этом профиле, но и распространённые форматы секретов: OpenAI-style `sk-…`, Google `AIza…`, Groq `gsk_…`, xAI `xai-…`, Hugging Face `hf_…`, GitHub tokens и AWS access key IDs.
- Маскируются значения в полях `api_key`, `access_token`, `client_secret`, `password`, `token`, заголовках `Authorization: Bearer …`, URL-параметрах ключей и блоках закрытых ключей.
- Очистка реализована отдельным `SecretRedactor`, используется форматтером HTTP-ошибок и покрыта автономными Java-тестами. Новых сторонних зависимостей и Android-разрешений не добавлено.
- Это best-effort фильтр текста ошибок, а не гарантия обнаружения любого неизвестного формата секрета; перед публикацией отчёта всё равно проверяйте текст.



## Новое в 1.33.0 — понятная диагностика API и отмена запросов

- При HTTP-ошибке AI Council показывает вероятную причину и следующее действие: проверьте ключ для 401, права доступа для 403, модель/URL для 404, квоту для 429 и размер задачи для 413.
- Ответ провайдера сохраняется как дополнительная подсказка, ограничивается 1200 символами и очищается от точно совпадающего API-ключа и распространённого Bearer-токена.
- Если пользователь останавливает запрос во время чтения ответа, приложение показывает отмену, а не путает её с неисправностью интернета.
- Тайм-аут, отмена и прерывание параллельного этапа получают отдельные сообщения.
- В проект добавлены 11 автономных проверок форматирования HTTP-ошибок.

## Новое в 1.30.0 — светлая, тёмная и системная темы

- В настройках появился выбор **«Как в системе»**, **«Светлая тема»** и **«Тёмная тема»**. Системная тема следует настройке Android, а два ручных режима имеют приоритет над системной.
- Светлая палитра адаптирует основные поверхности, поля, карточки, рамки, текст и семантические акценты. Яркий фирменный бирюзовый CTA и знак бренда остаются акцентными, а тёмные поверхности преобразуются в светлые.

- Логика выбора темы и адаптации цветов выделена в `UiThemePolicy` и имеет 29 автономных тестов, в том числе для контраста текста и системного режима.
- Новых внешних UI-библиотек не добавлено. Это нативная реализация средствами Android SDK.

## Новое в 1.28.0 — персональные эксперты и продолжение ответов

- В настройках каждого ИИ можно задать собственную роль и специализацию. Например, ИИ №1 может работать как программист, ИИ №2 — как критик или редактор, а ИИ №3 — как координатор и проверяющий выводы. Роли можно свободно редактировать; каждая ограничена 2000 символами и сохраняется локально.
- Во время запуска роль каждого участника фиксируется, поэтому изменение настроек во время текущей задачи не должно менять роли оставшихся этапов. Настройки ролей не входят в резервную копию истории/проектов и остаются в настройках данного устройства.
- Если модель сообщила, что ответ обрезан лимитом токенов, кнопка **«Продолжить обрезанный ответ»** попробует определить соответствующего эксперта и отправит запрос продолжения, попросив не повторять уже написанное. Это отдельный API-вызов и может расходовать дополнительные токены.
- Максимальный объём ответа на один вызов можно выбрать от 512 до 16384 токенов. Фактический предел задаётся моделью и провайдером: при ошибке из-за слишком большого лимита выберите меньшее значение.
- Уточняющие запросы привязаны к задаче завершённого результата, даже если поле нового черновика было изменено после ответа.
- Добавлены `ExpertRolePolicy` и `TruncatedAnswerPolicy`, а также 20 автономных тестов для пользовательских ролей и определения секции для продолжения.

## Новое в 1.27.0 — второй раунд взаимной критики в глубоком анализе

- Режим **«Глубокий анализ · 3 ИИ»** теперь отличается от обычного совета: после двух независимых ответов первые две модели параллельно проверяют ответы друг друга, а координатор получает оба исходных ответа и обе критики.
- Критика требует конкретных ошибок и логических скачков, отделяет подтверждённую ошибку от сомнения, фиксирует, что осталось неизвестным, и предлагает пересмотр позиции. Модель не должна соглашаться или спорить автоматически.
- Координатор дополнительно разделяет основания выводов: источник из предоставленного контекста, расчёт, входные данные или предположение. Запрещено выдумывать URL, цитаты, документы и номера страниц; совпадение моделей не считается доказательством.
- Ошибки или пропуски критического раунда явно маркируются в итоговом отчёте. Обычный режим совета сохраняет прежнюю более быструю схему; глубокий анализ делает дополнительные API-вызовы и может стоить дороже/занимать больше времени.
- Добавлена отдельная pure-Java политика промптов взаимной критики и 8 автономных smoke-тестов.

## Новое в 1.26.0 — экспорт отчёта и работа с отдельными ответами

- Результат можно сохранять как Markdown (`.md`) с заголовком, датой создания, версией приложения, выбранной стратегией, исходной задачей и полным ответом совета. Файл подходит для заметок, GitHub и дальнейшего редактирования.
- Экспорт использует системный Android Storage Access Framework: пользователь сам выбирает приложение/папку и имя файла. Новые разрешения на доступ ко всему хранилищу не добавлялись.
- В каждой карточке результата появилась отдельная кнопка копирования блока — можно скопировать ответ конкретного эксперта, не захватывая остальные части общего результата.
- TXT-экспорт теперь также содержит дату и стратегию. Экспорт и отправка используют фактическую задачу, на которую был сформирован ответ, даже если редактируемый черновик позднее изменился.
- Отчёт не добавляет настройки подключений и сохранённые API-ключи из настроек приложения. Содержимое задачи и ответа включается полностью: перед передачей отчёта другим людям проверьте его на секреты и личные данные.
- Добавлен независимый чистый Java formatter и 7 smoke-тестов формата отчёта, включая Unicode, структуру, пустые значения и защиту метаданных от внедрения дополнительных строк.

## Новое в 1.25.0 — прозрачные статусы и надёжная проверка конфигурации

- Статусы проверки chat endpoint и каталога моделей теперь независимы: получение списка моделей больше не перезаписывает результат проверки реального ответа модели.
- После выбора модели приложение отдельно показывает статус каталога и напоминает перепроверить chat endpoint. Результат каталога привязан к URL сервера и тому ключу, который реально отправляется API. Он помечается устаревшим, если URL или такой ключ изменился; локальный сервер не зависит от сохранённого облачного ключа.
- Результат проверки привязан к конфигурации, которую действительно тестировали: endpoint, ID модели и ключ. Для связи сохраняется только SHA-256 fingerprint, а не открытый API-ключ.
- При изменении параметров результат становится устаревшим сразу во время редактирования. Если пользователь возвращает все поля к ранее проверенным значениям, результат снова соответствует текущей конфигурации.
- Обработка завершения асинхронной проверки сравнивает текущие поля с исходными параметрами запроса, поэтому правка полей во время сетевого запроса не создаёт ложный статус «подключено».
- Добавлен отдельный pure-Java smoke test для fingerprint: стабильность, чувствительность к каждому полю, поддержка null и отсутствие открытого ключа.

## Изменение 1.21.0 — независимый выбор веб-поиска

- «Только локальные ИИ» блокирует только отправку задач публичным ИИ-провайдерам; она не меняет настройку поиска.

## Поиск в Интернете (улучшения 1.20.0–1.22.0)

- При включённом поиске параллельно опрашиваются Brave Search (если настроен API-токен), Tavily Search (если настроен API-ключ), MediaWiki/Wikipedia Search и DuckDuckGo Instant Answer через JSON API. HTML-разбор выдачи DuckDuckGo удалён в 2.0.0. В 2.0.0 поисковые API используют отдельный OkHttp transport с allowlist endpoint-ов; загрузка текста выбранных исходных страниц остаётся отдельным кодовым путём.
- Для запросов со словами вроде «сегодня», «latest», «за неделю/месяц», «this year» в Brave Search добавляется подходящий фильтр свежести (`pd`, `pw`, `pm`, `py`). Обычные запросы не ограничиваются датой автоматически.
- Язык поиска и язык интерфейса Brave выбираются по запросу (`uk`/`ru`/`en`). Статьи и ответы дедуплицируются по нормализованным HTTPS-адресам; отбрасываются явные локальные/служебные IP-адреса.
- Только в подробном режиме «Выдержки + текст до 2 страниц» приложение пытается получить HTML и извлечь текст максимум двух страниц с разных доменов (когда это возможно). Проверяются HTTPS, DNS-адреса, тип содержимого, размер ответа, redirects и время ожидания. Перенаправления повторно проверяются, чтобы не перенести запрос на localhost/приватный адрес. Контент и метаданные могут быть недоступны у некоторых сайтов.
- Выдержки ограничены и маркируются как неполные. Дата из метаданных не считается гарантированно правильной; поиск может показать дату страницы, дату получения или ничего. Модель должна различать эти случаи и считать содержимое страниц недоверенными данными.
- Ключи Brave Search и Tavily хранятся зашифрованными через Android Keystore. Brave получает токен только в заголовке `X-Subscription-Token` на фиксированном endpoint `api.search.brave.com`; Tavily получает ключ в Bearer-заголовке только запроса к `api.tavily.com/search`.

## Локальный ИИ

- Добавлена кнопка **«Получить список моделей»** рядом с каждым слотом ИИ. Она запрашивает OpenAI-совместимый `/models` endpoint, показывает обнаруженные идентификаторы и позволяет выбрать нужную модель одним нажатием.
- Совместимая маршрутизация работает с локальными серверами Ollama (`http://IP:11434/v1`) и LM Studio (`http://IP:1234/v1`). Список моделей берётся с сервера; приложение не скачивает веса языковых моделей. Для распознанных локальных HTTP- и HTTPS-endpoints ключ можно оставить пустым.
- Для локального endpoint приложение не передаёт сохранённые облачные ключи в заголовке `Authorization`, даже если ключ случайно остался в соответствующем поле настроек.
- Режим **«Только локальные ИИ»** блокирует публичные AI API и облачный follow-up, но **не выключает интернет-поиск**. Веб-поиск — отдельная настройка: можно использовать локальные модели вместе с поиском в Интернете или выключить поиск для полностью локальной работы. Если поиск включён, очищенная поисковая фраза отправляется внешним поисковым сервисам, а найденные материалы передаются выбранным моделям; сами запросы к моделям остаются на локальных endpoints. Во время выполняющейся задачи настройки временно нельзя переключить.
- Добавлены автономные проверки политики выбора моделей, URL модели и независимого выбора веб-поиска при local-only режиме.

**Ограничение:** в APK по-прежнему не встроены веса языковой модели и on-device inference runtime. Вычисления выполняются на локальном сервере Ollama/LM Studio (обычно компьютере в той же доверенной Wi-Fi-сети). Настоящий автономный запуск модели непосредственно внутри Android требует отдельного движка/ABI, выбора модели, измерений RAM/скорости и отдельного этапа разработки.

## Конфиденциальность и безопасность

- При включённом веб-поиске наружу отправляется очищенная поисковая фраза до 180 символов; источники и извлечённые выдержки могут передаваться настроенным ИИ-провайдерам. Не включайте поиск для конфиденциальных задач.
- Режим «Только локальные ИИ» ограничивает только AI endpoints. Интернет-поиск включается и выключается отдельно, независимо от выбранных ИИ-моделей.
- Облачные API требуют HTTPS. HTTP разрешён только для допустимых локальных адресов. HTTP в LAN не шифрует трафик; используйте доверенную сеть или HTTPS reverse proxy.
- При чтении страниц запрещены явные localhost/частные/служебные IP, используются ограничения размера и времени и повторная проверка редиректов. Это снижает риск SSRF, но не заменяет полноценную проверку сети/сертификатов на устройстве.

## Сетевая безопасность и конфиденциальность

- Облачные API требуют HTTPS.
- HTTP разрешён только для локальных хостов и приватных IPv4, для поддержки распространённых локальных серверов Ollama/LM Studio. Проверка адресов выполняется перед подключением, но HTTP в локальной сети не шифрует трафик: используйте доверенную Wi-Fi-сеть. При необходимости используйте HTTPS reverse proxy.
- В режиме «Только локальные ИИ» публичные адреса AI API блокируются до отправки задачи.
- Ключи Brave Search и Tavily хранятся зашифрованными и не включаются в резервную копию.
- При включённом веб-поиске запрос уходит внешним поисковым сервисам; сниппеты затем могут быть переданы выбранным ИИ-моделям.
